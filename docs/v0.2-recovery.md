# v0.2 post-compaction recovery extension

Status: **v0.2.1** implemented in `recovery/index.js`, registered as a preset
row with `enabled: false`. It is activated only by explicit config or the
test-only `DSH_ENGINEERING_RECOVERY_TEST=1` override.

v0.2.1 additions:

- Root-only delivery and subagent exclusion use the live DSH Agent registry
  (`ctx.agents.roots()`), not session-header or initiator-scope assumptions.
- Restart reconstruction scans the native session log once per root session.
- A successful `compaction/end` with no matching `engineering-recovery`
  `user/message` source is pending.
- A successful compaction followed by a durable recovery message is
  acknowledged and never replayed.
- Start/summary without a successful end is treated as partial and ignored.

## Verified lifecycle

In DSH 0.2.1-rc.3, `compaction-basic` writes these session events:

- `compaction/start`
- `compaction/summary`
- `compaction/end` (optional `error`)

Automatic pressure compaction runs on `agent/pre-step`; native overflow
recovery runs on `agent/request-error`. There is no Cordis `compaction/end`
event; observe the session event stream instead.

## Extension shape

A small preset-local `engineering-recovery` plugin:

```text
ctx.on("session/event", (session, event) => {
  if (event.type !== "compaction/end") return;
  if (event.data.error !== undefined) return;
  pending.set(session.id, event.data.compactionId);
});

ctx.on("agent/pre-step", async ({ agent, signal }, next) => {
  // read pending for agent.session.id
  // prepend one short recovery message to agent.inbox.next-step
  // clear pending before returning
  return next();
});
```

The reminder should ask the agent to:

- read the Task Recovery Ledger when present;
- reconcile it against Git status/diff and current test evidence;
- continue from the recorded next action;
- avoid repeating completed edits or inventing missing state.

## Safety invariants

- At most one reminder per successful `compactionId`.
- Never inject on a failed compaction.
- No recursive call to `compactNow`.
- No timer, background loop, network request, or credential access.
- No new summary call; native compaction remains the sole summarizer.
- The message is advisory; it cannot claim verification that was not observed.
- Feature is disabled by default and enabled only after isolated testing.

## Compatibility gate

Before enabling, verify against the installed runtime:

- `session/event` delivery for `compaction/end`
- `agent/pre-step` hook and `agent.inbox.prepend("next-step", ...)`
- `ctx.agents.get(session.id)` behavior
- `createUserMessage` source shape from `@deepseek-ai/dsh-llm`
- one-shot behavior across manual and automatic compaction
- no duplicate reminder after a resumed session

## Test plan

1. Synthetic `compaction/end` event → exactly one reminder at the next pre-step.
2. Failed `compaction/end` → no reminder.
3. Two successful compactions → two distinct reminders, never two for one ID.
4. Manual `/compact` → one reminder.
5. Overflow recovery → one reminder; no recursive compaction.
6. Restart/resume → no duplicate reminder from stale state.
7. A task that already completed a step → no re-execution.
8. Validation: targeted unit tests plus a disposable test session; no production
   profile or project state changed during the extension's acceptance run.

## Rollback

Remove the `engineering-recovery` plugin row and restart the test profile.
Native compaction and v0.1 behavior remain unchanged.
